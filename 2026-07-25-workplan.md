## Что делаем дальше

### Задача 1: Вилка в AGENTS.md

AGENTS.md должен содержать развилку:

```
Режим A: Последовательная обработка (текущий, рабочий)
  - Один скрипт, одна ссылка за раз
  - Запуск: python3 -m seed_pipeline.cli link-worker process --file <путь> --live-google
  - Работает стабильно, проверено на 15 ссылках

Режим B: Параллельная обработка (новый, для разработки)
  - Оркестратор определяет тип → кладёт в очередь по платформе
  - Воркеры запускаются параллельно: Instagram-воркер, TikTok-воркер, YouTube-воркер
  - Каждый воркер берёт свою очередь и обрабатывает независимо
```

По умолчанию — Режим A (последовательный). Режим B включается флагом.

### Задача 2: Параллельный оркестратор

Новый файл: `services/seed_pipeline/src/seed_pipeline/link_worker/parallel_orchestrator.py`

Логика:
1. Прочитать все link-файлы со статусом `new`
2. Router определяет тип контента
3. Разделить на очереди по платформе (instagram_queue, tiktok_queue, youtube_queue)
4. Запустить воркеры параллельно (asyncio или multiprocessing)
5. Каждый воркер обрабатывает свою очередь последовательно (с rate limiter)
6. Собрать результаты, проверить нумерацию

Важно:
- Rate limiter остаётся per-platform (Instagram 240 сек, TikTok и YouTube без ограничений)
- Если один воркер упал — остальные продолжают
- Финальная проверка нумерации после всех воркеров
